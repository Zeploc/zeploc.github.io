App · Personal app · project Taro

Atlas

A local-first, JARVIS-style voice assistant. Atlas runs on my laptop with a local model: type to it, hold a key to talk, or say "Hey Atlas". It looks things up on the web and in the weather, and nothing in the conversation leaves the machine; only search terms and place names do. Its personality is dry, lightly British and warm, with a humour dial.

What it does

  • Hands-free: Whisper listens for its name, with a 30-second follow-up window
  • Barge-in: "Atlas, stop", "hold on" or talking over it cuts it off, without hearing itself
  • Answers at once, checks the web or the weather, and says "Confirmed." only when the results back it up
  • Remembers checked facts with a date: "As of earlier today…" without a new search
  • PC actions: timers, reminders, media keys, volume, and opening apps and folders
  • Reads the PC's own gauges: GPU temperature and load, CPU, disk and battery

How it works

Understand first
A small trained "reader" turns each phrase into a structured frame (what was heard, the intent, references, what is unclear). Plain, tested code decides what happens; the language model only phrases the answer.
The reader
Qwen3 0.6B fine-tuned with LoRA on about 1,000 examples: about 84% of frames fully right in about 200 ms, against 73% in 2.3 s for a 9B model.
Hearing and voice
faster-whisper with voice-activity detection to hear; Kokoro on the GPU to speak; a 4B model through Ollama to talk.
Speed
About 0.3 s to the first token of a quick reply and about 2.2 to 2.6 s to the first spoken word hands-free. Reusing one connection saved about 330 ms per model call.
Desktop app
Tauri 2, TypeScript and Three.js, with no UI framework. The animated orb is a web component that talks to the core over a local WebSocket.
Privacy
Microphone audio is never saved. The WebSocket accepts only local connections and refuses browser pages.

Process

  1. Measure, then choose

    A model bake-off chose the speaking model; a wake test across five names chose "Atlas" (28 of 28 wakes, 3 false out of 45).

  2. Build in phases

    Phases 0 to 4 built in the first days: chat, voice, hands-free, lookups and the desktop app.

  3. The pivot

    Real use showed one root cause: Atlas spoke before it understood. Research into dialogue systems led to the understand-first design.

  4. Test the model like code

    A graded evaluation that fails on any wrong case, a frame evaluation of every field, a hearing test, and a room simulation with echo and noise.
