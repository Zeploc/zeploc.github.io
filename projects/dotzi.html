App · Personal app · Android and Windows

Dotzi

A personal life-management app that starts as a "task forcer". It holds my tasks and, during free time, picks one at random (weighted). It warns first, then takes over the screen until I start the task or say I'm busy. The phone is the base; a Windows desktop app is the companion. Its face is a blobby character that chirps.

About the project

Never out of the blue. Busy beats force.

— Dotzi's design rules

What it does

  • Escalating nudges: a warning, a due notification, then a full-screen takeover that returns if ignored
  • A weighted draw: priorities weigh 1, 3 or 9, and waiting tasks gain weight each day
  • Due and repeating tasks, with overdue tasks pushed first
  • Today's energy (1–5) sets how many tasks, and how big, I get that day
  • Bedtime and sleep: wind-down and bedtime takeovers, a sleep estimate, an automatic alarm and a gym push
  • Busy blocks: I enter when I'm busy and Dotzi works out the free time

Features

  • Blob moods

    The blob's face follows the nudge: happy, impatient, grumpy, focused, or "shh".

  • Takeover that sticks

    Works over the lock screen, survives a restart and fires in battery-saving Doze mode.

  • Desktop companion

    A tray flyout, a Win+Shift+D shortcut, wide layouts and a takeover across every monitor.

  • Done and left today

    A day strip and progress bars, worked out by running the real planner forward.

  • Follows me between devices

    The phone plans, the PC mirrors it, and the nudge goes to the device I'm using.

  • Generated sounds

    The chirps come from a synthesiser in shared code; alarm sounds are generated for day, dusk and night.

How it works

Shared code
One Kotlin Multiplatform module holds the domain, data, UI, theme, the blob and the sound synthesis. Android and Windows add thin platform code.
Reliable alarms
Every nudge uses the alarm-clock API, because the test phone delayed ordinary exact alarms by up to 75% of the wait.
Local sync
Phone and PC talk directly over home Wi-Fi (WebSocket, found by mDNS). Each row carries a hybrid logical clock; the latest write wins. No cloud database.
Pairing and encryption
P-256 keys, a Noise-style handshake, HKDF and AES-256-GCM, with no new library. The phone picks the matching number from three.
The blob
Drawn in code on a canvas, with props such as a mug and a dumbbell.
Testing
kotlin.test with hand-written fakes, headless Compose UI tests, a failing test before each bug fix, and manual check tables for the takeover, link, pairing and sync.

Process

  1. Choosing the stack

    Compared Kotlin Multiplatform, Flutter, MAUI and Tauri before starting (14 Oct 2026).

  2. Designing in rounds

    About 25 rounds of HTML mock-ups, with each decision logged as agreed, rejected or open.

  3. Worst-case testing

    Tested on a phone chosen for how hard it kills background apps.

  4. Building in steps

    Walking skeleton, scheduler, sync, pairing, energy, sleep, busy time, then a Windows installer, all in October 2026.
