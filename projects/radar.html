App · Gadget · a gift for a friend

Radar

A DIY LED matrix display, inspired by the FlightWall, built as a birthday gift for a friend. It shows the closest flight overhead with the techy details, then rotates through a radar sweep, a clock with the weather, NFL scores and custom messages. An ESP32-S3 drives the panels, fetches free public data itself and serves its own web UI to any phone on the home Wi-Fi: no app, no cloud, no accounts.

What it does

  • The closest flight: callsign, type, registration, route, altitude, speed and distance
  • Smooth numbers: altitude and distance are estimated between reports, so the digits keep ticking
  • A radar sweep with real blips at their true bearing and distance, military planes in red
  • Alerts for military aircraft, rare types and emergency squawks
  • Live NFL scores with a touchdown flash
  • A clock with live weather, and rainbow messages sent from the phone

The simulator

More features

  • First-run setup

    The board opens its own Wi-Fi hotspot with a setup page.

  • Phone web UI

    A live copy of the panel, with skip, pin, brightness, a location map and debug tools.

  • Safe updates over Wi-Fi

    An update installs only after a press of the board's button, and rolls back on its own if the new firmware fails.

  • Never blank

    The display degrades instead of freezing: a red pixel marks old data, and failed requests back off politely.

How it works

Portable core
All logic (data, parsing, screens, drawing) is plain C++ with no board code, so it runs on the board and in a PC simulator.
Two cores
Networking runs on one core and drawing on the other, passing only the latest data between them.
Free data
adsb.fi (adsb.lol as fallback) for flights, adsbdb for routes, Open-Meteo for weather, ESPN for NFL. No API keys.
Memory budget
512 KB RAM, 8 MB PSRAM, 16 MB flash. JSON is parsed into a fixed PSRAM arena, so polling never allocates.
Web UI
Vite, TypeScript and Preact with Leaflet maps, compressed into the firmware under a 500 KB budget.
Simulator
Runs the real core and serves the real web UI with a virtual LED panel, using live data if wanted.

Hardware

  • Two 64×32 P3 HUB75 panels make a 128×32 strip, 384 × 96 mm
  • An ESP32-S3 dev board (16 MB flash, 8 MB PSRAM), wired with jumper wires and no adapter board
  • One 5 V supply with a shared ground; brightness is capped on USB power
  • Pinout mapped with a multimeter, with a step-by-step wiring guide for a first-time wirer
  • A smoked acrylic diffuser and frame to come

Process

  1. The board is the brain

    A phone-driven display would freeze when the phone sleeps, so the board fetches everything itself.

  2. Ship in two steps

    A single-panel demo on a video call on the birthday, then the finished two-panel display by hand about a month later.

  3. Decide on paper

    A log of 51 numbered decisions, each weighing the options.

  4. Test every pixel

    Golden-frame images for every screen at both sizes, Playwright tests on WebKit and Chromium against the simulator, and long soak tests.

  5. Bring-up

    Parts ordered 18 Oct, hardware brought up 28 Oct, then Wi-Fi setup, radar, alerts, NFL, the web UI and updates.
